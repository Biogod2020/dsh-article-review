# 项目模式（原型，2026-10-31）

把一篇论文当作一个项目，从材料走到投稿。故事流是审阅的中心，正文写好后仍然以它为准。

## 六个阶段

| 阶段 | 做什么 | 离开前的清单（只作提醒） |
|---|---|---|
| 材料 | 登记数据、结果、已有的图、目标期刊和读者 | 有材料；期刊与读者已填 |
| 骨架 | agent 根据材料起草故事流：核心论点、5–9 拍、每拍的分论点、论据（做法 / 支持 / 限定 / 缺口）和面板 | 有核心论点；每拍都有分论点 |
| 论点与图 | 围绕故事流改论点和图；请编辑、审稿人、读者三个角色审阅 | 核心分论点都有充足支持；缺口有负责人；每张图已定主图或扩展数据 |
| 成文 | agent 按骨架逐拍成文；每段记下它陈述哪些分论点、按哪一版论点写的 | 正文与骨架同步；正文数字都在登记表 |
| 阅读审核 | 按阅读顺序读正文，旁边是这段对应的面板；选中文字写意见 | 段落都已审 |
| 投稿 | — | 意见都已处理 |

阶段由作者推进，可以退回。清单未完成也能进入下一阶段，未完成的项会留在概览里。

## 界面

- **故事流**（默认）：左列是各拍，右边是撑起这一拍的分论点卡片。卡片上显示：
  - 论据强度条：绿 = 充足，黄 = 部分，灰 = 缺失或缺口，红 = 风险；
  - 已审圆点：绿 = 已审，橙 = 审后有修改，灰 = 未审；
  - 未处理意见数、等你确认的回应数、缺口数、“正文未同步”。

  点卡片打开详情：论点陈述（审后有修改时显示相对你上次审过版本的逐词差异）、审稿人会问的问题、按类别列出的论据和面板缩略图、正文中陈述它的段落、意见和输入框。
- **图**：主图、扩展数据、未定三栏。每个面板标出引用它的分论点；没有任何论据引用的面板标红，可以就地“关联到论据”（选分论点再选论据）或“标为备用”；没有面板的分论点列在顶部。点面板放大。可以把图移到另一栏。
- **正文**：按节列出段落，每段左侧是它陈述的分论点。
  - 论点在段落写好后改过：段落标红，可以“起草改写”，或点“对照后确认仍然一致…”。后者会先列出写这段之后论点改了什么（逐词差异），读过再确认。
  - agent 起草的改写不会直接替换正文：段落处显示新旧逐词对照，作者点“接受改写”或“放弃”。草稿起草后段落若又被改过，草稿作废。
  - 不在登记表中的数字黄色标出。点击后可以：登记（写明是什么和出处）、只在这段忽略、全篇忽略、记为待核对；“下一个未登记数字”按阅读顺序逐个跳转。
  - 还没成文的拍可以一键让 agent 写。
- **阅读**：衬线正文，右侧是当前段落陈述的分论点和对应面板。选中文字后点“✎ 写意见”。
- **意见**：分“人的意见”（作者、协作者、对话，默认）和“模拟审阅”（编辑、审稿人、读者）两组，顶栏的意见数只计人的意见和等你确认的回应，模拟审阅另计“AI n”。
  - 按状态（未处理 / 已回应 / 已关闭 / 不采纳）筛选，可以“只看我写的”；
  - 勾选若干条交给 agent，执行前弹窗列出这些意见和可能改动的单位；审稿人的主要意见（涉及证据）只能单独处理；
  - agent 回应后状态变为“已回应”。回应下方列出这次实际修改的单位（点击直达该处及其差异）和待确认的正文改写草稿；作者看过再关闭或重新打开。
  - 概览页不再提供“处理全部意见”。
- **更多**：数字（未登记数字与登记表）、历史（每个版本的执行者、原因、改动单位、回应的意见）、论点网络（分论点之间的依赖，作为扩展功能保留）。

## agent 的工作方式

- 写意见时有两个按钮：“交给 agent 修改”会记下意见并立刻让 agent 处理这一条；“只记下意见”只做记录（协作者只有“提交意见”）。
- 处理意见时 agent 改论点和图；改动若让已写好的段落不同步，会自动为这些段落起草改写，挂在同一条意见下，等作者逐段接受。
- 论点和图的修改直接写入，记录原因和执行者，并标为“审后有修改”，直到作者确认；作者的复审单位是“自上次审过以来的变化”。正文例外：改写都以草稿形式等待作者接受。
- 每个提示词都要求模型同时站在三个外部位置看稿件：决定是否送审的期刊编辑、逐条核对证据的审稿人、第一次阅读就要读懂的目标读者。
- 三个审阅角色各负责一个问题：
  - 编辑：故事与取舍；
  - 审稿人：证据强度与过度表述；
  - 读者：读不读得懂，读者设定为非英语母语的邻近领域研究者。

  它们的意见进同一个意见列表。
- 成文风格：领域内英语母语专家的水平，同时让非英语母语读者读得舒服；只用登记过的数字；分论点的说法不超过证据强度。
- 已有文章：由 agent 反推骨架，切分正文并把每段对应到分论点，然后从“成文”或“阅读审核”阶段接着做。

## 协作

- 协作者只能写意见。协作者视角顶部有一行说明。
- 作者确认已审、推进阶段、让 agent 修改。
- 作者可以把意见指派给某个人（如合作者或学生）；意见页可以筛“指派给我的”。

## 第三轮补充（2026-10-31）

- 计数口径统一：
  - 概览“待你处理”把人的意见和模拟审阅分开计；
  - 未登记数字分“正文”“论点与论据”两项；
  - 清单里的意见数也分人和模拟审阅。
- 段落一律显示为“节标题 · 第 n 段「开头几个词…」”，不再显示内部 ID。
- 数字分诊：
  - “数字”页可以让 agent 先把数字分成结果、方法参数、引用编号、其他四类（只作提示）；
  - 可以按类筛选、全选，写一条理由后批量忽略；
  - 单个数字的浮窗显示 agent 的分类，忽略时必须写理由（记入历史），处理后自动跳到下一个。
- 改写草稿：
  - 右侧并排显示这段应当陈述的分论点和对应面板；
  - 可以“改几个词再接受”，历史中记为“修改后接受”；
  - 从意见跳来时，顶部显示“来自意见…”和“返回意见”；
  - 一条意见关联的改写全部确认后，提示“满意，关闭这条意见”。
- 进入“投稿”时，如果清单还有未完成的项，必须写明理由，记入历史。其他阶段仍然只提醒。
- 论点和图的修改仍然直接写入并标为“审后有修改”。这是作者有意选择的工作方式，不改成逐条建议。

## 原型的边界

- 演示外壳：`demo/`。
  - `server.ts` 用本地 HTTP 和一个兼容 OpenAI 接口的模型执行 agent 任务；
  - DSH 插件中，同样的任务会交给对话里的 agent（模型工具尚未接入）。
- 已有文章的导入目前由一个脚本完成，还没有做成 skill。
- 界面只有中文。

## 在 DSH 中运行（2026-10-31）

- 侧栏多了一个“论文项目”标签页，与“阅读、批注与修改”并列。输入工作区里含 `project.json` 的文件夹即可打开，用的是同一套界面。
- 面板里的“让 agent 做”，会作为一条消息发进当前对话，由对话里的 agent 用 `project_*` 工具完成：
  - 编辑、审稿人、读者的意见用 `project_comment` 记录；
  - 论点和图的修改用 `project_apply`，同时逐条回应意见；
  - 段落改写用 `project_draft` 提交，以草稿形式等作者确认。
- agent 这一轮结束后，面板自动刷新。
- 如果 `project_apply` 让某些段落和论点不同步，工具的返回值会列出这些段落，并要求 agent 在结束前为它们起草改写。只写在提示词里时，模型会跳过这一步；放进返回值之后，实测会起草。
- 从已有稿件初始化（2026-11-01）：开始页只有一个“论文”入口，面板里填稿件、图、意见、研究仓库和新项目文件夹。
  - 每个路径旁有“浏览…”，逐层浏览工作区，选文件或文件夹。
  - 新项目文件夹默认 `papers/<稿件名>-project`；稿件叫 `main.tex` 之类时，用它所在文件夹的名字。默认名已被占用时自动加编号。作者改过的名字不会再被覆盖，清空则回到默认。
  - 输入时就检查（`paper-project/check-init`）：路径不在工作区内（符号链接按实际位置算）、找不到、文件和文件夹弄反、新项目文件夹已存在或已是项目，都直接显示在对应输入框下，按钮不可点；新项目文件夹和图、意见或稿件位置重叠时只提醒。交给 agent 前服务器再查一遍。
  - 项目必须在当前工作区里，因为 agent 和面板只能读写工作区；放到别处需要在那个目录打开新的工作区。
- 初始化改为“边读边抄”（2026-11-01：工具提取的文字和图片在面板里很难看）：
  - 脚本不再拆段落、不再抽图。`init_project.py` 只建空项目和 `reading/`：PDF 每页一张图，LaTeX/Word 的图转成 PNG，文字层只用来查拼写和数字，并供检查对照。
  - agent 用 `read_image` 逐页看，按项目格式（纯文本、一段一行、断词接好、公式写成 Unicode、不带 Markdown/LaTeX）自己抄进 `project_apply`；措辞照抄原文，不改写。
  - 图和面板靠看：`page_tools.py grid` 给页面画千分比坐标网格，agent 选框后用 `page_tools.py crop` 裁剪（PDF 页从原 PDF 高分辨率重渲染），裁完自己看一眼再定。面板逐个裁，论据链接到具体面板。
  - `check_project.py` 对照文字层检查：哪页漏抄（图里的文字不算）、哪段措辞对不上（改写）、粘贴痕迹（行尾断词、换行、连字、LaTeX/Markdown、页眉、正文里的图注、跨页截断的段落），以及裁图为空、面板等于整图、稿件里的图在项目中缺失。不通过时 agent 回到对应页改正，直到通过。
- 初始化按轮次推进（2026-11-01）：模型做长任务会提前收工（实测抄 3 页就自己把 goal 标成完成），而且看过的页面图片一直留在对话里。所以由面板驱动：
  - 先一轮准备，然后每轮 4 页左右（或两节源文件），之后一轮整理论证、一轮检查；agent 每结束一轮，插件在 `agent/status` 变为 idle 时发下一轮。
  - 参考文献页按位置识别（References 标题之后、附录之前，且多数行像引文），不发给 agent；Related Work 里 “et al.” 再多也不会被误判。
  - 某一轮什么都没记下，就重发一次；还没有就暂停。用户在对话里自己发消息（子 agent 的通知不算）、或中止一轮，也会暂停。面板上显示进度，可以暂停、继续、停止。
  - 进度存在 `reading/job.json`，DSH 重启后打开项目可以点“继续”。
  - 检查不通过时，下一轮消息会逐条列出剩下的错误，最多两轮修正。消息里写明只能用本 skill 的脚本和 `project_*` 工具：实测 agent 被“面板”这个词带去用了逐段审阅的 paper-figure-panels，再停下来向用户要 Markdown 稿件。
  - 检查会看裁图四边：边缘一整行有内容，说明切掉了图的一部分，或混进了图注、正文、相邻面板。
  - 实测（James Zou 组 Hybrid Reasoning Agents，arXiv 2610.18861，45 页 PDF，gpt-6-luna）：
    - 抄录 40 节、141 段，覆盖稿件正文 96%，措辞不符 0 段；裁出 27 张图表、35 个面板；6 拍、12 个分论点，30 条论据全部链接到面板；
    - 修正轮之后检查通过；之后加上的面板四边检查又找出 5 个切到相邻面板或坐标轴的面板，留给下次的修正轮。
- 换模型复测（2026-11-01，Claude Haiku，看 skill 是否只适配 gpt-6-luna）：DSH 测试环境里没有 Haiku 模型，于是让 Claude Code 的 Haiku 子代理跑同一个 skill、同样的脚本、同样的轮次消息（由 `validation/harness/rounds.ts` 生成，与插件相同），`project_*` 工具改用命令行桥 `validation/harness/project-tool.ts`。工具实现已从宿主抽到 `src/project/tools.ts`，两边调用的是同一份代码。
  - 两者都完成了全部 11 轮抄录、论证和检查：
    - 正文覆盖都是 96%，措辞不符都是 0。Haiku 抄了 46 节 150 段，gpt-6-luna 40 节 141 段。
    - 图表：Haiku 31 张、36 个面板，裁图零错误；gpt-6-luna 27 张、35 个面板，还有 5 个面板切到了邻图或坐标轴。
    - 论证：Haiku 14 个分论点、63 条论据（45 条链接到面板）、81 个登记数字、93 段已对应；gpt-6-luna 12 个分论点、30 条论据、16 个数字、69 段。
    - Haiku 还找出了稿件里真实存在的不一致，例如 §6.3 写 AUROC 差距在 0.022 以内，而 Table 7 弱监督器那一行差 0.068。
  - skill 和检查里有几处是照 gpt-6-luna 的写法定的，换了模型才暴露，已改：
    - 公式多的证明段会被误判为改写（Unicode 公式和 PDF 文字层对不上），措辞比对改为只比三个字母以上的单词；
    - `$359 → $98` 被当成 LaTeX，Haiku 只好改写成 “USD 359”，现在 `$…$` 里有 TeX 符号才报；
    - Haiku 用 `e_{t+1}` 这种 TeX 下标，原规则查不出来，现在会报，skill 也写明上下标用 Unicode 或括号；
    - 修正轮的消息改为按问题种类合并：原来同一条建议重复 20 次，有 8 KB；
    - 裁图错误也让检查以状态 1 退出。
  - 有两处 Haiku 的判断和 gpt-6-luna 不同，skill 都允许：Figure 5/6 的 4B/8B/14B 子图 Haiku 留作整图一个面板，gpt-6-luna 拆成三个面板；Algorithm 1 Haiku 作为图像块保留。
- 阅读页改成分页阅读（2026-11-01）。做法与常见的预印本阅读器相同：
  - 每节另起一页，正文按约 220 词切页（动态规划，避免很短的尾页），超过 300 词的段落在句末切开；作者和单位这类短行用小号字显示。
  - 右栏显示本页正文引用的图表面板。能识别 “Figure 2D”“Figures 6 and 7”“Table 9”“Extended Data Fig. 4b”，有对应字母的面板就显示面板，否则显示整图。悬停引用会高亮对应卡片，点击会滚到那张卡片。
  - 本页段落陈述的分论点所依据的面板默认折叠；本页不引用任何图（比如摘要）时，先显示其中 6 个。
  - 支持目录、上一页/下一页（按钮显示相邻小节名）、← → 翻页、A−/A＋ 调字号，并记住读到哪一页。选中文字写意见、查看段落的分论点和意见放在右栏的“这段”标签里。
  - 切页和引用识别的代码在 `src/project/reader-pages.ts`，有单元测试。
- 构建：在 DSH 0.2.1-alpha.4 源码的 `packages/experimental/paper-review` 下进行，包名临时改为 `@deepseek-ai/dsh-experimental-paper-review`，以通过客户端打包对实验包的检查。测试安装在独立的 DSH profile 中。
